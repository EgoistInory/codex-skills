# 番茄小说签约与推荐质量优化调教原则规范

本规范旨在解决番茄小说（从**签约评估过审**到**推荐流算法分发防断推**、**完本模式陷阱规避**及**AI低质内容治理**）全流程的工业化标准。不仅解决“如何签约”，更重点解决“签约后如何避免被推荐算法判定低质而终止推荐”的深层工程问题。

---

## 1. 核心定位与审核模型拆解：签约审核 vs 推荐算法流的双层剪刀差

在番茄小说（字节跳动分发体系）中，很多作者面临一个巨大困惑：**“为什么小说顺利签约了，刚给推荐没多久就被算法直接打上‘低质’并终止推荐？”**

必须彻底认清平台内部**两套完全独立、维度不同的审核漏斗**：

```
[投稿作品] 
    │
    ├──▶ 【第一关：签约审核 (人工主编 + 粗筛规则)】
    │     ├── 考核重点：主线是否自洽、有无违规擦边、有无断头烂尾（“内容没有收尾”）、字数与排版规范。
    │     └── 结果：签署版权合同，获得平台“准生证”（静态合法性）。
    │
    └──▶ 【第二关：推荐流风控与读者留存算法 (字节跳动推荐引擎)】
          ├── 维度 A：微观文本统计学特征（NLP 算法检测）
          │     ├── 困惑度（Perplexity, PPL）：文本过于顺滑、预测概率极高 ──▶ 判定 AI 模板生成
          │     └── 突发性（Burstiness）：句子长短方差与段落长短方差趋近于零 ──▶ 判定机械工业废话
          ├── 维度 B：冷启动读者微观行为数据（300 ~ 2000 基础曝光池）
          │     ├── 黄金三章（前3000字）划走率 / 15~30 秒跳出率
          │     └── 第 1 章、第 5 章、第 10 章完读率
          └── 终局判定：【高跳出率】 + 【低 PPL 平滑文本】 ──▶ 自动触发“内容未达推荐标准，推荐流程已终止”。
```

## 2. 六大质量与工程闸门（The 6 Quality Gates）

任何需要冲刺签约、抗住推荐流算法检验的小说，必须严格通过以下六道刚性质量闸门：

```
[源文] ──> [1. 格式编码门] ──> [2. 去AI恶疾门] ──> [3. 微观突发性门] ──> [4. 母语语域门] ──> [5. 爽点与终局门] ──> [6. 连载发布策略门] ──> [爆款推荐级正文]
```

---

### 门禁一：纯文本格式与编码硬闸（Zero-Tolerance Format Gate）

| 检验项 | 刚性标准 | 错误示例 | 正确规范 |
| :--- | :--- | :--- | :--- |
| **正文格式** | 纯文本，严禁任何 Markdown | `**他冷笑一声**`、`### 第3章` | 纯中文段落，段首不缩进或使用中文标准全角排版 |
| **书名号禁令** | 正文与章节标题严禁出现 `《》` | `012-读《本草纲目》.md`、`《侍亲规约》` | `012-熟读本草.md`、`侍亲字约` 或 `“侍亲规约”` |
| **文件编码** | 强制 UTF-8 无 BOM，LF 换行 | UTF-8 with BOM、CRLF 混杂 | 严格以 UTF-8 纯文本读写，杜绝 Latin-1 乱码（如 `ã€`） |
| **单章字数** | **2,050 ~ 3,800** 非换行字符 | 单章 < 1,900 字（短小卡签约）或 > 5,000 字（拖沓注水） | 黄金商业体量：**2,400 ~ 3,300 字/章** |
| **章节命名** | 三位补零序号加短横加纯标题 | `vol1_ch001.md`、`第3章 《夜战》.md` | `003-夜战青龙.md`（三位数字开头，兼容自动化发布工具解析） |
| **标题零赘述** | 标题文字严禁包含中英文数字章节号 | `033-第三十三章 山祠避雨.md`、`第33章 第三十三章...` | `033-山祠避雨.md`（标题只留纯标题文字，后台自带章节序号） |
| **正文首行** | 正文首行直接进入小说第一段，严禁标题行 | 首行写 `第1章 风雪夜盘死人账` 或 `# 第1章...` | 首行直接为小说正文第一自然段（杜绝 App 双标题撞车） |

#### 标题质量、正文首行与工具兼容专项军规：
1. **标题零冗余（严防双重中英文/数字章节号）**：
   - 番茄小说后台发布系统在录入章节时，系统界面自带“第X章”前缀，后台标题输入框**只填写干净的标题文字本身**。
   - 严禁在章节标题中重复塞入 `第X章`、`第XX章`、`第三十三章` 等序号（如 `033-第三十三章 山祠避雨，卸甲疗伤` 属于完全赘述）。此类双重序号会导致平台审核判定为格式粗制滥造、App 章节目录多重重复。
2. **正文首行无标题硬闸（杜绝阅读器双标题穿帮）**：
   - 正文 Markdown/纯文本文件内容，第一行**严禁出现任何章节标题行**（无论是 `# 标题` 还是纯文本 `第1章 标题`）。
   - 正文第一行必须直接从小说故事的第一自然段开门见山切入。若正文开头保留标题，读者在番茄 App 阅读器中会同时看到“系统渲染的大标题”和“正文第一行小标题”，造成双标题翻车事故。
3. **自动化发布工具文件名兼容规范（Parser & Importer Compatibility）**：
   - 章节文件名必须严格采用三位补零数字开头：`NNN-纯标题.md`（如 `001-风雪夜盘死人账.md`）。
   - 严禁使用 `vol1_ch001.md`、`chapter-1.md` 等非标准命名前缀，否则自动化发布工具（如 `fanqie-auto-publisher` 等）在正则解析时无法提取章节序号，会导致工具报错“未识别到章节/没有章节”。

### 门禁二：破除四大宏观 AI 恶疾（Anti-AI Macro Slop Gate）

1. **恶疾 1：账本审计体（Accounting/Auditing Prose）**
   - **病症**：角色在对白或旁白中大段汇报银钱分厘、利润折算、程序合规辩解。
   - **药方**：**将财务计算转化为物理动作与神态冲突**。写银钱压在掌心的铜锈味、破旧布包抖落时的窘迫、铜板砸在柜台上的脆响，以及因几文钱引发的家庭尊严较量。
2. **恶疾 2：日历天气模板句开篇（Calendar-Weather Formula）**
   - **病症**：每章第一句机械固定为“X月X日清晨/午后，某某地的风霜/细雨……”。
   - **药方**：**强制使用中途切入法（In Media Res）**！必须从人物动作、异常声响、器物碰撞、激烈对白或身体感官直接开门见山；日期自然化入第二、三句的动作细节中。
3. **恶疾 3：口号式升华与机械完结标签**
   - **病症**：章末出现“属于他们的时代大幕终于拉开”、“这不仅是一张桌子，更是两代人的硬骨头……”等空洞排比，或正文机械打上 `（全书完）`。
   - **药方**：**严禁任何议论文式的升华，删除所有（全书完）标签**。结尾必须收在具象的生活画面、呼吸感或悬念余韵上。
4. **恶疾 4：“并非……而是……”等反刍式二元排他否定腔**
   - **病症**：AI 极度习惯使用“他要的并非金银，而是这世道的一丝公道”、“这并不意味着妥协，而是更加隐秘的潜伏”。
   - **药方**：**直接断句，删除否定前置**，只说人物实际做了什么、拿了什么。将心理独白还原为物理动作与冷硬选择。

### 门禁三：微观统计特征与去悬浮词闸门（Micro-Slop & Burstiness Gate）
> **本门禁是攻克“算法推荐流判定低质断推”的生死核心。**

#### 1. 彻底清除 6 类高危 AI 悬浮套话词库（平台算法敏感字典）：
* ❌ **抽象心理与气场套话**：`眼神中闪过一丝（复杂/警惕/冷意）`、`空气中弥漫着`、`无形的气场`、`达成了微妙的平衡`、`心中暗自（思忖/冷笑）`、`深知……意味着什么`
  * 改造：全部换为物理生理反应（喉结滚动、手心里冷汗黏腻、脚趾抠紧鞋底、茶杯在桌沿滑脱半寸）。
* ❌ **议论文式排比递进**：`这不仅是……更是……`、`殊不知……更是一场……`、`这一切的背后……`
  * 改造：彻底删除，直接写主角得了什么利，对方折了什么脸面。
* ❌ **平滑过渡连接词**：`随着时间的推移`、`与此同时`、`悄然生变`、`在不知不觉中`
  * 改造：生硬切入，无需过渡，通过人物的一个动作或一句喝问直接换场。

#### 2. 段落长短方差重构（Breaking Uniformity & Elevating Burstiness）：
* **严禁整篇 60~80 字对称等长排版**。AI 生成的文本往往每段都是三行半，方差几乎为零。
* **强制注入人类视觉呼吸节奏**：
  * **单字/极短句独立成段**：用于最关键的冲突点与决断时刻。
    > 例：  
    > “不行。”  
    > 两个字砸在青石板上，硬得像块生铁。
  * **长短句剧烈交错**：急促的连续短对白，紧跟一段长且细节饱满的器物与环境交锋。

#### 3. 黄金三章（前 3000 字）防跳出军规：
* **前 500 字内必须爆发不可逆的生存危机或屈辱冲突**。
* 严禁开篇大段交待世界观、身世背景、宗族历史。读者划走只需要 15 秒，开篇第一屏必须让读者看到主角退无可退的压迫。

### 门禁四：母语小说语域与现场质感（Register & Scene Gate）

1. **对白密度指标**：
   - 每一章中文双引号对白（`“……”`）至少 **20 对以上**（推荐 28 ~ 45 对）。
   - 杜绝“旁白概括式推进”。
2. **架空古典与市井语域净化**：
   - 严禁现代企业与行政词汇渗透：
     - ❌ 禁用：`指标、方案、供应链、岗位职责、统一调配、权限、流程、试用期、观察期、风险把控`
     - ✅ 替换为：`门规、名册、流水、分例、主事、规矩、立字为凭、契卷、押金、盘账、点货`
3. **物象与触感（市井泥土味）**：
   - 融入鲜活方言顿挫、市井口语倒装与人间烟火（冷饭结的油皮、衣衫腋下的酸味、老茧划过木料的沙沙声）。

---

### 门禁五：爽点账单与终局闭环（Payoff Ledger & Ending Gate —— 专克“内容没有收尾”）

1. **每章内心核验“爽点账单”**：
   - 压迫是谁？读者期待什么？主角独有何种专业反制？对手实质损失什么？主角与身边人拿到什么真金白银/地位提升？
2. **终局四大闭环要素（必查）**：
   - **核心道具/意象终极重现**：开篇屈辱道具（如《座上人》中篮底藏的新布鞋），终章必须在主角自主的席面上让父母堂堂正正换上，坐上首座主位！
   - **人际情感彻底清偿**：昔日刻薄亲友自然退场，核心盟友出师成家。
   - **双重落点闭环**：物质自立（不再依附他人） + 精神救赎（灵魂归家）。
   - **终章留白与呼吸感**：严禁写“全书完”，收束于沉静的人间日常动作中。

### 门禁六：商业发布模式防坑铁律（The Release Strategy Iron Law）
> **此条为平台实战中最昂贵的商业认知教训。**

#### 🚨 铁律：严禁新书首发使用“完本模式”！必须一律伪装为“连载模式”分批发布！

| 维度 | 完本模式（一次性全本发书）陷阱 | 连载模式（分批定时发布）生命线 |
| :--- | :--- | :--- |
| **试错容错率** | **零容错率（一锤子买卖）**。冷启动一旦被机器初筛判定“未达标”，立刻触发停推。 | **无限试错迭代**。可随时根据读者反馈修改前文。 |
| **编辑修改权限** | **系统永久锁死！** 完结后作者端不能更新正文、不能改章节、不能改回连载。 | **完全开放**。前 10 万字可以连夜重写前三章，动态优化留存率。 |
| **算法推流机制** | 缺乏“追更行为”，冷启动测试池极严，算法极易放弃。 | 依靠每日更新提醒唤醒读者，享有 1 万字、10 万字、20 万字多轮动态推荐重算。 |

* **正确做法**：即使手里已有 100 章、200 章完整书稿，也**必须在番茄以“连载中”状态新建作品**，设置定时发布，每日自动放出 2~3 章（4,000~6,000 字）。在连载过程中密切监控前三章留存，一旦数据下滑随时无损修改前文！

## 3. 已完本停推作品的紧急自救指南（签约责编人工通道）

如果一部作品已经在完本模式下被系统判定“未达推荐标准，推荐流程已终止”，作者前端界面已被系统写死，**唯一的自救通道是联系签约责编进行人工后台重置**。

### 1. 权限事实与沟通心理学
- 前端作者自服务界面已锁死，但**后台责任编辑拥有最高管辖权限**（编辑可以后台执行“取消完结状态”、“重置为连载中”或“开放章节修改权限”）。
- **禁忌**：切勿向编辑抱怨平台模型、切勿争辩“我这不是 AI”。
- **策略**：以“新签约作者主动优化开篇、提高读者留存”为切入点，恳请编辑后台协助转为连载。

### 2. 建议沟通话术模板：
```text
责编大大您好！我是刚刚完成签约的作品《书名》（书号/作品ID：XXXXXX）的作者。
非常感谢平台对本书故事架构的认可！收到完结推荐流程终止通知后，我认真复盘了初期的读者阅读数据，发现此前一次性全本导入时，前几章的排版节奏、市井口语与开篇压迫感还有极大的提升空间。
因为合同刚刚签署，非常希望能让这部作品跑出应有的收益。恳请责编大大能否协助在后台帮我将作品状态临时重置为“连载中”（或临时开放前5章修改权限）？
我已将前文全面优化完毕，修改后希望能重新提交审核，配合平台跑出更好的完读数据。给您添麻烦了，非常感谢！
```

## 4. 标准重构与审查工作流（Surgical Rewrite Workflow）

```
[步骤1: 运行全书扫描脚本] 
       │ 自动定位：字数异常、书名号、日历开头、Markdown、弱对白、微观AI悬浮词
       ▼
[步骤2: 建立缺陷矩阵表]
       │ 划分【需彻底重写章节】与【仅需首尾精修章节】
       ▼
[步骤3: 卷轴式并行重构]
       │ 重写旧稿，打碎长句提升 Burstiness，拔除抽象心理词，前置冲突
       ▼
[步骤4: 全量回归测试]
       │ 运行 audit 脚本，验证 0 Markdown、0 书名号、0 模板开头、0 悬浮套话
       ▼
[步骤5: 连载形式分批封包发布]
       │ 严禁完本模式首发，按连载模式日更发布，保持前文无损迭代生命线
```

## 5. 升级版自动化质检脚本与规范化命令

在项目根目录或书籍目录中，调用本 skill 内置的自动化质检工具 `scripts/audit_fanqie_quality.py`：

```bash
# 1. 全维度质检（扫描指定正文目录，含格式、微观AI悬浮套话、日历开头、字数、对白）
python scripts/audit_fanqie_quality.py --dir ./books/借席/正文

# 2. 严格模式（任何警告直接视为失败）
python scripts/audit_fanqie_quality.py --dir ./books/借席/正文 --strict

# 3. 检查单章
python scripts/audit_fanqie_quality.py --file ./books/借席/正文/001-旧木生香.md
```

### 脚本核心审查标准字典：
- `CHAR_MIN`: 2050 字符
- `CHAR_MAX`: 4000 字符
- `MIN_DIALOGUE_QUOTES`: 20 对双引号
- `BANNED_MARKDOWN_REGEX`: `^(#{1,6}\s|>\s|[-*+]\s|\*{1,2}|`{1,3})`
- `BANNED_BOOK_MARKS`: `《.*?》`
- `CALENDAR_WEATHER_REGEX`: `^\s*[0-9一二三四五六七八九十百]+月[0-9一二三四五六七八九十]+[日号]?.*?(清晨|一早|午后|傍晚|深夜|微风|寒霜|秋阳|晨雾|雨水)`
- `AI_SLOP_ENDINGS`: `（全书完）|时代大幕|拉开了大幕|这不仅是.*?更是|仰不愧于天`
- `ACCOUNTING_PROSE_REGEX`: `并非.*?而是|不是.*?乃是`
