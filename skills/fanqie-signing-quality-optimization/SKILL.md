# 番茄小说质量预防与签约诊断

帮助作品在动笔和扩写时减少原创性、结构、人物、阅读体验与连续性问题；已有正文则先诊断根因，再决定修订范围。目标是提高故事质量，不承诺签约、推荐或收益，也不把去套话当作规避平台检测的方法。

## 使用时机与交付

本 skill 可由 `fanqie-novel-workflow` 在选题、小样、写前、阶段复核和投稿前调用，也可单独使用。按任务只读相关材料，保留现有目录、事实源和写作授权：

| 阶段 | 需要检查 | 最小交付 |
| --- | --- | --- |
| 新书策划 | 分类与读者承诺、可辨识卖点、能力边界、分阶段冲突 | 可执行的策划修正与小样范围 |
| 开篇小样 | 进入主线、主动选择、局部兑现、继续阅读的理由 | 引用样章的结论与下一批范围 |
| 逐章写前 | 因果、信息来源、能力依据、代价延续、解法差异 | 补入章纲的短检查或场景修正 |
| 阶段/新卷 | 情节同构、题材承诺、人物成长、跨模型连续性 | 受影响阶段的修订方案 |
| 拒签/全书诊断 | 投稿资料、通知类型、结构和代表性正文 | 有章节证据的优先级诊断 |

全书诊断先看简介、总纲、目录与各卷转折，再精读开篇、关键节点和结尾。说明实际阅读范围；抽样不能冒充已逐章通读。没有正文证据时，把“能力万能”“五卷同构”“多模型割裂”列为待验证假设，不能直接写成拒签原因。

每项问题给出位置与短引文/纲要证据、对阅读的影响、修复范围和复核方法。结论用“通过 / 待修 / 待验证”；结构性待修项先修根因，再扩写依赖它的剧情。不要虚构总分或通过概率。

## 先区分评估环节与证据

- 完本模式可能先有完结审核；安全审核、作品质量评估和后续推荐评估是不同环节。不要把安全通过当作质量合格，也不要把综合质量退回等同于 AI 检测命中。
- 模型内部审稿、脚本扫描、真实读者反馈、编辑意见、平台通知分别记录；没有外部证据时标记“市场未验证”。
- 官方公开规则、项目约定和内部经验必须分开标注。平台是否使用某模型、PPL/Burstiness 阈值、固定曝光池或跳出秒数，若无可靠公开依据就保持未知。
- 不推断行业签约率的变化幅度，也不从一个退回提示推导该书的具体失败原因。

## 九项质量检查：按创作阶段应用

这些是内部审稿维度，不是平台公开的九道固定机器门槛。按当前阶段选用，不要求每章重复全书检查。细目见 [references/signing-quality-checklist.md](references/signing-quality-checklist.md)。

### 1. 格式与交付兼容

确认正文可按项目工具正确导出，编码、顺序、章节边界和标题无歧义。项目要求纯文本时清除 Markdown；是否在源文保留标题、导出首行标题、文件名形式，以实际导出器为准。

中文书名号 `《》`、正常中文标点、CRLF、少对白或章长本身不证明作品低质或违反签约要求。只有明确项目规则才设为对应交付约束，不为了过扫描误删正常表达。

### 2. 原创表达与有效内容

检查是否照搬人物组合、核心剧情、连续桥段；是否依靠机械扩写、复述和大段说明增加篇幅。重复句式和套话只是审稿线索，需要看它是否遮住人物行动、信息变化与情绪后果。

专业数字、程序与制度说明要让读者理解人物正在争取什么、为什么会失败、结果影响谁；保留必要推理，不把所有专业内容都删成感官描写。

### 3. 阅读节奏与信息密度

开篇尽快建立处境、欲望和阅读期待；章节应有有效推进。句段长短随动作、对话、情绪与场景变化，不刻意打乱节奏以提高“突发性”。

默认约 2,200–2,800 字可作试写预算参考；超长、过短或整齐段落需要结合题材和内容判断。不开“前 500 字必须人命危机”“每章必须 20 对对白”等统一处方。

### 4. 中文语感与题材语域

引用拗口原句，检查搭配、主语、人物声音、叙事距离与世界内用语。古代经商、现代金融和科幻管理有不同语境；词语命中不能直接裁定题材错位。

不强制每章动作开头，不把所有连接词、旁白或全知提示列为禁词；修的是重复、空泛和不合场景的表达。

### 5. 期待兑现与收尾

写前说明本阶段读者在等什么，写后用人物得失、关系变化、真相或行动空间证明兑现。蓄势章允许延后兑现，但要有进展和后续位置。

全书收尾按本书主线、伏笔和人物关系验收；不强制所有故事都以手艺自立、亲人和解或静态日常结束。结尾标签是否保留由项目与投稿格式决定。

### 6. 签约路径与发布约束

策划商业试验前核对账号等级、作品创建时间、可选签约模式、提交字数及完结条件、正文锁定/修改规则和剩余申请次数。只记录当前证据，不默认连载模式可选，也不承诺编辑能重置状态或恢复推荐。

截至 2026-10-26 已核对的官方来源：

- [签约评估帮助中心](https://fanqienovel.com/writer/zone/help/article?rank1=10189&rank2=10191&rank3=0)：区分审核与质量评估；每本作品共 3 次签约申请机会。实际操作前复核后台与最新说明。
- [2026-10-12 签约模式调整通知](https://fanqienovel.com/writer/zone/article/7695623157880733758)：新建作品 Lv.0/Lv.1 适用完本签约，Lv.2 及以上有模式选择；已创建作品可按通知继续连载。
- [完本签约模式上线通知](https://fanqienovel.com/writer/zone/article/7682324588209913881)：用于核对完本条件与流程，不能将内部小样预算当作申请门槛。

规则快照不替代实时核对。网络不可用或后台未知时记录待核实项，可以继续内部策划与试写，不自行投稿或改变发布模式。

### 7. 受众承诺与题材发展

检查书名、简介、标签、开篇和各卷是否兑现同一种核心期待。允许跨类型，但尺度扩展须有因果、能力积累和人物关系承接。

不按男女读者刻板规定题材。风险是突然更换主要看点或理解门槛，不是女频不能写制度、男频不能写情感。

### 8. 人物弧光、能力边界与后果

主角的技能、资源、信息和协作必须有来源；跨领域破局须有学习、试错或可靠协作者，不能凭专业名词全知通关。对手有独立目标、合理策略和有效反制。

重要选择需要取舍与延续到后文的后果。允许主角强大，不强制致命误判、死亡、破产或每场胜利附带惨剧；核查的是压力是否可信、成长是否有过程、代价是否被下一章抹平。

### 9. 小样、阶段验证与投入边界

商业试验默认先写 3–5 章的小样，约 8,000–12,000 字供预算参考，再按既有节拍分批扩写。这个范围可调整，不是平台的签约资格。条件不满足时不拿正式申请做试读。

用户要完整长篇或全自主写作时，保留其目标，在授权内设置内部复核点并继续。缺外部反馈时标记“市场未验证”；商业试验达到预算仍缺证据时保留产物并报告，不自动扩大体量。

样章之后与每个小阶段复核主线承诺、解法差异、能力增长与人物声音。多次失败先找共同根因，不用重复全文润色代替结构修复。

## 自动化扫描的用途与调用

`scripts/audit_fanqie_quality.py` 是只读的格式与写法线索扫描器。它不能评估原创性、人物弧光、情节同构、签约资格、真实读者留存或推荐算法，也不会修改正文。

从当前安装的 skill 目录定位脚本，用绝对路径调用；不要误调用小说项目中同名旧脚本。例如将 `<skill-root>` 替换为实际路径：

```text
python "<skill-root>/scripts/audit_fanqie_quality.py" --file "<book-root>/正文/001-标题.md"
python "<skill-root>/scripts/audit_fanqie_quality.py" --dir "<book-root>/正文" --min-chars 1800
python "<skill-root>/scripts/audit_fanqie_quality.py" --dir "<book-root>/正文" --historical --body-only
```

默认章长、对白和段落统计仅是内部提醒。`--historical` 才开启古风语域词表提醒；`--body-only` 才要求源文首行无标题；`--min-chars` 调整项目章长提醒。`--strict` 将所有提醒提升为本地失败，只在项目明确采用时使用，不能将其说成官方门槛。

退出码 0 表示没有扫描阻断项，可能仍含需审阅提醒；退出码 1 表示格式/读取错误，或严格模式下有提醒。无匹配文件也失败。报告必须说明扫描范围、实际问题及内容审稿尚未覆盖的部分，不能输出“全部达到番茄签约与推荐标准”。

## 修订与重申

按影响顺序处理：主线/因果/承诺 -> 人物与冲突 -> 场景信息 -> 语言与格式。先在代表性章节验证修法，再按受影响范围扩展，保留事实源和已发布约束。

质量退回后记录通知、已用次数、具体证据、修改前后和剩余问题。提出再次申请的判断依据，不自动耗用次数，不保证换模型或全文去套话就能通过。

Codex 与 Gemini 使用同一套文件证据和阶段结论；不要声称某插件已安装或某命令可用，除非已在当前环境确认。
