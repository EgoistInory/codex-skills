# 番茄小说写前质量与分阶段扩写

用于新书策划、全自主长篇、开篇重构、新卷规划及阶段复核。日常续写只读取“逐章写前检查”和已有检查记录；不要每章重新调研规则、评估全书或生成额外报表。

## 前置预防与后置审查的分工

本文件属于创作 workflow：在内容生成前安排好要写什么、如何避免已知缺陷。
`fanqie-signing-quality-optimization` 仍是正文形成后的详细质量审查与提审整改工具。保留其九大质量闸门、清单、脚本及 Codex/Gemini 通用支持，不为前置控制重构它。

把签约失败暴露的问题转成写前可执行约束，而不是在写前跑一遍全书后置审查：

| 后置检查关注点 | 写前安排与落点 |
| --- | --- |
| 格式、字数与工具兼容 | 开书时确认源文、标题、导出约定和本轮章长；写完再校验实际文件 |
| 账本审计体、空泛套话、机械开场 | 章纲写清人物行动、现场阻力、有效信息和变化，避免只列概念与汇报结论 |
| 母语语域与阅读节奏 | 先确定世界内用语、人物声音和场景节奏，写后再引用原句细审 |
| 爽点与终局闭环 | 事先安排读者期待、局部兑现、关键伏笔与终局承接，不等完稿才补闭环 |
| 发布模式与试写策略 | 核实适用模式，在既定目标内安排小样与阶段复核，不以试签约代替试读 |
| 题材纯度与受众预期 | 在简介、总纲和卷纲中明确持续兑现的核心看点与尺度转折 |
| 人物弧光与真实代价 | 提前设定能力来源、信息盲区、学习协作、选择取舍和后果延续 |
| 情节同构与跨模型割裂 | 比较相邻阶段的解法，并在交接时恢复人物动机、口吻、视角和事实 |

专项审查在样章、阶段稿和提审前按需触发，结论回灌章纲与状态；逐章起草复用相关约束，不重复加载整套后置清单。两个 skill 的分工由项目文件传递，在 Codex 与 Gemini 中保持一致。

## 决策与记录

每次检查给出以下一种结论，并用大纲位置或正文原句支撑：

- 通过：本阶段关键问题已由材料回答，进入已约定的下一写作批次。
- 待修：列出具体缺口、影响范围和最小修复；修复后复核该问题，再扩写依赖它的剧情。
- 待验证：证据不足。没有外部反馈时明确“市场未验证”，可以在本轮预算内继续试写；关键设定或因果缺失时先补齐依据。

将简短记录并入现有章纲、审查 summary、`CURRENT_STATUS.md` 或等价文件，不强建一套平行状态系统。阶段记录至少包含：

```text
阶段/检查范围：选题、开篇样章、当前小阶段或卷纲
本轮预算：章数或字数，以及下次复核点
结论：通过 / 待修 / 待验证
证据：具体纲要位置、章节与短引文；反馈则注明来源和时间
问题与修复：根因、受影响剧情、已修什么、尚缺什么
验证层级：内部审稿 / 真实读者试读 / 编辑意见 / 平台通知
下一步：下一批范围；哪些剧情仍依赖待修项
```

“通过”只表示本阶段可以推进，不表示签约成功、存在读者需求或收益可期。换模型或交接时复用记录；读不到证据就补查，不沿用无依据的“全绿”。

## 1. 选题与生产约束

在 `PROJECT_BRIEF.md` 或现有简介中明确：

- 目标读者和主分类、核心阅读体验、一句话卖点，以及与常见模板相比的具体差异。新意应进入人物决策或冲突机制，不只是换名词。
- 主角想要什么、阻碍来自谁、为何由这个人推动故事、什么选择会让其失去东西。
- 核心能力从何而来，在哪些领域有效，依赖什么信息、资源、协作者与学习；不能把会算账自然等同于精通国家财政、海贸和军事。
- 预计体量与主要转折，各阶段如何改变人物目标、关系、对手策略或解决问题的方法。避免“危机变大 -> 主角精确解题 -> 搭档兜底 -> 换更大危机”的复用。
- 用户要的是商业试验还是完整创作；前者确定可承受的试写与修订预算，后者在既定总目标下设置内部复核点。

涉及签约策略时，先核对当日官方公告和该账号、该作品适用规则，记录来源、核对日期、可选模式、提交条件和已知剩余次数。不知道账号等级时将资格记为待核实，仍可策划和写样章。

允许情感、经商、权谋等交叉题材。判断标准是简介、开篇和后续是否持续兑现同一种核心期待，以及扩大尺度的转折是否有铺垫；不要把男女频偏好刻板化为题材禁区。

## 2. 开篇小样

默认先写 3–5 章，约 8,000–12,000 字可作预算参考，题材或用户已有规划不同时调整。不将这个范围当作番茄申请资格，也不为卡字数删掉必要因果或填充空话。

样章交付前，按正文证据检查：

1. 读者能否尽快理解人物处境、当前欲望、阻力和继续看的理由；不强制前 500 字出现债务、人命或打脸。
2. 简介承诺的核心看点是否已在场景中出现；伏笔和世界观是否帮助理解而非压住主线。
3. 主角有没有主动选择、信息缺口与可信解法；配角能否基于自己的利益拒绝或反击。
4. 是否出现一次与题材匹配的局部兑现，例如关系进展、线索成立、资格改变、反击收益或重要选择的后果；不是所有题材都要三章打脸。
5. 开篇悬念是否能由后续计划兑现；中后期是否还有新的困难与人物变化，而非只有扩大敌人规模。
6. 用片段说明语言、视角、对话和人物反应是否一致；局部华丽表达不能抵销结构缺口。

先修样章暴露的最大问题，再进入下一批。需要独立审稿且环境和授权允许时，可隔离起草上下文；同一模型换编辑视角仍属于内部审稿。

## 3. 逐章写前检查

在现有章纲中补短条目或内部列出，不输出给正文读者：

| 检查 | 要回答的问题 |
| --- | --- |
| 本章变化 | 人物的处境、关系、信息或可选行动具体改变什么？ |
| 因果与能力 | 信息从哪来，为什么这么做，凭哪些已建立的能力、资源或协作完成？ |
| 阻力与选择 | 对手独立想要什么，主角的盲区在哪里，有哪些可行但有取舍的选择？ |
| 后果连续 | 本章收益与代价影响后续哪一步；旧伤、失信、债务或资源损失有没有凭空消失？ |
| 非重复 | 与近几章相比，冲突、取证、协商、行动或情感推进的方法有何实质变化？ |
| 表达边界 | 当前视角知道什么，角色会怎么说；专业说明如何影响现场决定？ |

确认这些问题有可写答案后进入 workflow 的爽点账单。不要把检查表固化为每章相同的段落顺序；过渡、日常、悬疑蓄势章按其功能验收。

重要历史、金融、法律或技术设定若决定破局结果，须有世界内规则或可核实依据；无法确认时明确假设并限制剧情依赖，不能让现实制度名词直接替主角完成推理。

## 4. 阶段复核与扩写

在小样后、每个剧情小阶段结束和新卷开始前复核，默认以 5–10 章为一个批次参考，可适配既有节拍。用户明确要写完整本时在授权内继续，不把每个节点变成确认请求。

- 将相邻阶段简写为“目标 -> 阻力 -> 选择 -> 解法 -> 得失 -> 关系变化”。若换掉地名和敌人后仍是同一故事，修冲突机制，不只换措辞。
- 核对读者承诺和主线仍在推进。经商扩展到制度问题、个人冲突扩展到公共危机时，检查能力积累、尺度转折和人物关系是否承接。
- 核对主角的认知局限与成长，反派是否会学习和反制。代价必须影响选择，但不强制每次胜利都死人、破产或制造虐点。
- 从开篇、近期转折和刚改写章节抽样对照人物声音、视角、关系和专有词；换模型后的润色不得悄悄改动动机、事实或能力边界。
- 区分结构、人物、信息呈现和句子问题。先修结构与因果，再做语言润色；避免反复全文重写。

有外部反馈时记录读者读到哪里、何处停下、能否复述期待、想继续读的具体原因，以及样本来源。样本少或来源偏时保留不确定性；不凭模型模拟读者捏造完读率或商业验证。

全自主模式没有真实反馈时保留“内部检查通过、市场未验证”。在预算内继续创作；商业试验达到预算仍无足够证据时保留已有产物，报告待决策点，不自动加码数十万字。

## 5. 投稿与重申

- 只在用户授权实际投稿且后台条件满足时提交；试读、模型好评和脚本退出码不能代替签约评估。
- 按通知区分完结审核、安全审核、质量评估和推荐评估。综合退回不等于平台认定 AI 文，也不证明某个假设就是拒签原因。
- 质量退回后先定位有章节证据的问题、修复范围与验证结果，再考虑剩余申请机会；不因单纯换模型、删套话或补字数就重申。
- 不承诺联系编辑即可重置模式、修改权限或推荐；只据实际后台与官方支持答复处理。

## 官方规则与经验的边界

截至 2026-10-26，核对到的公开来源：

- [签约评估帮助中心](https://fanqienovel.com/writer/zone/help/article?rank1=10189&rank2=10191&rank3=0)：安全审核与质量评估分开；质量关注原创表达、逻辑、结构和阅读价值；每部作品的签约申请机会有限。实际提交前复核最新页面与后台。
- [2026-10-12 签约模式调整通知](https://fanqienovel.com/writer/zone/article/7695623157880733758)：新建作品的 Lv.0/Lv.1 作者适用完本签约，Lv.2 及以上有模式选择；通知同时保留已创建作品的连载安排。不能把“连载首发”设为通用硬门槛。
- [完本签约模式上线通知](https://fanqienovel.com/writer/zone/article/7682324588209913881)：用于进一步核对完本模式的条件和流程；不可用内部试写字数代替提交要求。

这些规则会变化，日期是证据快照，不是永远有效的默认值。内部样章预算、章长提醒、词频、对白数、段落长短仅帮助审稿；不声称掌握平台内部模型、PPL 阈值、固定流量池或签约概率。
