# Tesla Paint Shop 车衣制作

将用户创意或参考图转成可导入的车机外观贴图。核心是 **AI 产生设计素材，代码固定官方 UV 与 Alpha**。仅把生成图缩到 1024 或改名为 PNG，不能补救错误的拆解件布局。

## 先固定正确模板

- 确认车型、年款和配置，再从 [Tesla 官方 custom-wraps](https://github.com/teslamotors/custom-wraps) 选择模板。老款 2024 Model Y 对应 `modely`，不能误用 `modely-2025-*`；其他车型同样独立选择。
- 读取当前官方说明，保存模板原始字节、来源路径、提交版本与 SHA-256。用户上传模板可通过字节哈希与官方原件比对；不凭文件名或外观判断。
- 检查实际尺寸、颜色模式和 Alpha。保存原始透明通道，包括半透明边缘；不得重画轮廓、移动部件或二值化边缘。

## 设计与方向

1. 从请求提取主题、基色、参考主体、文字和左右布局关系。历史中的 IP、银灰基色是案例，不是所有设计的固定要求。
2. 用当前环境正式可用的生图能力生成图案/主体素材，或读取用户参考图。生成失败如实报告；对话里的生图权限不等于部署站点的运行时权限。
3. 先形成可评估的示意，再按原模板坐标工程化合成。用户已授权自主制作时，可自行选择合理布局，不需要每个微调都再确认。
4. 先用指定基色覆盖所有车身件，再分部件贴素材。常用操作是裁切、平移、等比缩放、局部旋转和蒙版合成；合成参数要可重放。
5. 分别处理左右前后车门。**位置对称、中心对称、镜像和文字阅读方向是不同约束**。上车后的文字须从车外站立视角可正常阅读；不要用整张 UV 镜像处理所有部件。
6. 单独检查文字层。参考图里已经烘焙的文字会随图案镜像，不能因新增文字层没翻转就宣称参考图文字也正常。必要时先拆出文字、按部件重新排布。
7. 用不对称字母/前后箭头制作方向校准图；检查每个目标部件。二维展开只证明其自身映射，不能冒充准确车型三维预览或实车导入证据。

## 工程化整理与校验

默认交付：**PNG / RGBA、1024×1024、小于 1,000,000 字节、模板外透明、Alpha 与选定官方原件逐像素一致**。文件名含 `.png` 保守控制在 30 字符内，只用 ASCII 英文字母、数字、空格、下划线和短横线。

本 skill 附带 [scripts/finalize_wrap.py](scripts/finalize_wrap.py)，用于已经按官方坐标完成的设计画布：铺基色、强制原模板 Alpha、压缩并独立解码复验、生成 JSON 报告。它不会推断部件语义、修正倒字，或把错误 UV 自动变正确。

选择能导入 Pillow 的 Python；优先使用环境已配置的文档/图像运行时，不为了运行脚本修改全局依赖。

```sh
python scripts/finalize_wrap.py \
  --template /task/modely-template.png \
  --template-sha256 VERIFIED_TEMPLATE_SHA256 \
  --model modely \
  --design /task/composed-uv.png \
  --base-color '#aeb5bf' \
  --output /task/ModelY_Design.png
```

- `VERIFIED_TEMPLATE_SHA256` 换成实际核验值；不是示例密钥。
- `--design` 必须是同尺寸、同布局的工程化画布，脚本拒绝缩放 UV。
- 默认只做无损压缩。若超限，允许在保留 Alpha 的前提下加 `--allow-rgb-quantization` 减少 RGB 色阶；交付时说明发生了颜色减少，并重新检查外观。
- 脚本不覆盖已有成品或报告；选新文件名保留修改前结果。
- 字节大小、PNG 格式、RGBA、尺寸和 Alpha 从实际编码文件验证；报告哈希须与交付文件一致。方向和实车结果单独记录，不能由这个脚本推断。

## 最终交付

给出 **实际可点击的成品下载链接**，以及必要的校验摘要和报告链接。Codex 本地文件使用 `[下载成品](/absolute/task/ModelY_Design.png)`；ChatGPT 使用其真实文件附件下载链接；网页提供实际下载控件。不要只返回路径、把不存在的文件加 `sandbox:` 前缀，或将示意截图当成成品。

报告车型与模板版本、尺寸、真实字节数、透明度比较和颜色压缩情况。没有实车导入证据时明确说明未验证。当前官方说明里的导入途径应再核实后给出，不能擅自操作用户车辆或格式化 U 盘。
